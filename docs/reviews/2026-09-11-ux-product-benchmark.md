# 듀엣 UI/UX·기능 보강 재검토

작성일: 2026-09-11 · 검토 기준 커밋: `478c2be`

듀엣은 기본 기능의 폭이 충분하다. 다음 개선의 중심은 **작업 결과를 신뢰할 수 있게 만들기, 반복 작업의 맥락을 저장하기, 검색·수집·실행을 연결하기**가 적절하다. 크로스플랫폼 가치도 화면 모양의 통일보다는 같은 작업을 같은 개념과 결과로 수행하는 데서 강화된다.

이번 검토는 현재 코드·설계·기존 9월 5일 리뷰 대조와 경쟁 제품 공식 웹 문서 확인을 바탕으로 했다. 앱 실행, 경쟁 제품 설치, 화면 캡처 비교, 전송 속도 측정, Windows/macOS/Linux 실기 테스트는 수행하지 않았다. 아래 ‘확인’은 코드 경로 확인을 뜻하며, 시각적 밀도·접근성·체감 성능은 실기 검증이 필요한 제안이다. 우선순위·규모·기대 효과는 검토자의 판단이다. 제품 코드 변경 없이 보고서만 추가했다.

## 1. 먼저 판단할 사항

| 순서 | 보강 항목 | 이유 | 우선순위 |
|---|---|---|---|
| 1 | 원격 편집 세션의 파일 식별·업로드 상태 | 동명 파일 충돌 및 저장 성공 여부 불명확 | P0 |
| 2 | 원격 검색 메타 필터의 정확성 | 존재하는 항목을 검색 결과에서 제외할 수 있음 | P1 |
| 3 | 작업 센터 + 실패 항목만 다시 처리 | 현재 작업 종료 후 결과를 다시 확인하기 어려움 | P1 |
| 4 | 교체·복원 문구 정합성 + 폴더 병합 | 폴더 통째 교체와 파일 덮어쓰기의 의미가 다름 | P1 |
| 5 | 이름 있는 작업환경 + 설정 이동 | OS를 바꿀 때 작업 맥락까지 유지 | P1 |
| 6 | 검색 결과 일괄 작업 + 혼합 소스 Shelf | 이미 갖춘 기능 사이의 반복 클릭을 줄임 | P1 |

P0는 데이터 정확성 때문에 먼저 재현·수정할 항목, P1은 일상 생산성과 신뢰에 직접 영향을 주는 항목, P2는 후속 편의 개선이다. 모든 P1을 동시에 구현하라는 뜻은 아니다.

## 4. 현재 구현에서 우선 고칠 지점

### R01. 원격 편집의 동명 파일 충돌과 저장 상태 — P0

**확인:** `src-tauri/src/services/edit_session.rs:24`의 임시 경로는 연결 ID와 basename만 포함한다. `commands/system.rs:325`가 그 경로에 다운로드한 내용을 쓰고, 원격 파일마다 감시 작업을 시작한다.

같은 연결에서 `/project-a/config.json`과 `/project-b/config.json`을 열면 같은 임시파일 경로가 된다. 두 번째 열기가 첫 편집본을 덮거나, 감시 타이밍에 따라 같은 로컬 변경을 서로 다른 원격 경로에 업로드할 위험이 있다. 코드상 경로 충돌은 확인했으며 원격 파일 오염은 실기로 재현하지 않았다.

**추가 확인:** `edit_session.rs:40`은 원격에 직접 `write_full`을 호출한다. 이 감시 경로에는 원격 변경 기준값 비교·저널 기록이 보이지 않으며, 업로드 성공/실패는 `tracing` 로그로만 남는다. 연결 종료 시 감시 루프가 끝나므로 사용자는 에디터에서 저장한 것과 서버에 반영된 것을 혼동할 수 있다.

**제안:**

- 원격 전체 경로와 연결 식별자를 포함하는 세션 키, 충돌하지 않는 임시 디렉토리, 중복 열기 시 기존 세션 재사용.
- ‘편집 중 / 업로드 대기 / 반영 완료 / 실패 / 감시 종료’를 작업 센터에서 표시.
- 업로드 전 원격 버전 재확인. 다른 프로세스가 변경했다면 비교·다른 이름 저장·명시적 교체를 제공.
- 원격 편집 덮어쓰기의 복구 정책을 별도 정의. 기존 copy/move 파일 Replace 예외를 원격 편집까지 자동 확대하지 않는다.

**완료 기준:** 같은 서버의 동명 파일 두 개를 서로 다르게 수정해도 각 원격 경로에만 반영된다. 연결 단절·외부 변경·앱 종료 후에도 미반영 편집본과 다음 행동을 확인할 수 있다. 로컬 편집기의 atomic save도 포함한다.

### R02. 원격 파일명 검색에서 메타 필터가 잘못된 결과를 만든다 — P1

**확인:** `commands/search.rs:101`의 `build_remote_index`는 원격 항목을 전부 `File`, 크기 `0`, 수정일 `None`으로 저장한다. `services/file_index.rs:401`은 그 값에 `SearchOpts::accepts`를 적용한다. `core/search.rs:44`는 최소 크기에 못 미치거나 날짜가 없는 항목을 제외한다.

현재 UI는 원격에서도 ‘폴더만’, ‘1MB 이상’, ‘최근 7일’ 같은 조건을 제공한다(`SearchPanel.tsx:84,122`). 따라서 원격 **파일명 인덱스 검색**에서 조건을 켜면 존재하는 대상이 빠질 수 있다. 내용 검색은 별도 경로이므로 같은 결론을 일괄 적용하지 않는다.

**제안:** 우선 미지원 조건에 ‘이 서버 인덱스에는 정보 없음’을 표시하고 비활성화하거나, 실제 메타데이터 검색으로 전환한다. 이후 서버별 기능 확인을 거쳐 종류·크기·수정일을 수집한다. 모르는 값을 0바이트 파일로 취급하지 않는다.

**완료 기준:** 같은 fixture를 로컬과 SSH에 두고 파일/폴더·크기·날짜 필터 결과를 대조한다. 실제 0바이트와 크기 미상을 구분한다. 인덱스가 오래됐거나 연결이 끊겼을 때 결과의 기준 시각을 표시한다.

### R03. 완료·부분 실패를 다시 확인할 작업 센터 — P1

**확인:** `useTaskEvents.ts:67,110`에서 완료·실패 처리 후 `remove(id)`를 호출하고 `TasksBar.tsx`는 활성 작업만 표시한다. 저널 히스토리는 있지만 작업별 성공·실패 상세 보고서와는 다르다. `core/ops.rs:389`는 실패를 단일 에러 문자열로 합치고 처음 5개까지만 이름을 포함한다. 현재 Task IPC는 목록과 취소를 제공한다(`commands/tasks.rs`).

**사용 상황:** 300개 파일 중 일부가 권한 오류로 실패했을 때, 사용자가 잠시 다른 일을 했다 돌아와 어떤 파일을 다시 보내야 하는지 확인하기 어렵다.

**제안:** 접을 수 있는 작업 센터에 진행/완료/부분 실패/실패/취소를 보존한다. 호스트와 원본→목적지, 성공·실패·건너뜀 개수, 상세 항목, ‘실패한 항목만 다시 시도’, ‘목적지 열기’를 제공한다. 토스트에는 해당 작업으로 가는 액션을 붙인다.

프론트에서 끝난 작업을 보존하는 것은 1차 개선이다. 정확한 항목별 재시도는 백엔드가 구조화된 결과와 원본 식별자를 남겨야 하므로 별도 작업이다. 재시도할 때는 현재 파일 상태로 다시 plan한다.

**완료 기준:** 부분 실패 후 성공 항목을 중복 처리하지 않고 실패분만 재시도한다. 취소와 실패가 구분된다. 이력을 닫았다 열어도 결과를 확인할 수 있다. 영속 이력을 추가할 때는 보관 한도도 함께 둔다.

### R04. 파일 교체·폴더 교체·Undo 설명의 정합성 — P1

**확인:** 현재 정책은 copy/move의 기존 **파일** 교체는 영구 덮어쓰기, 기존 **폴더** 교체는 백업 보존 및 Undo 가능이다(`CLAUDE.md §4`, `core/ops.rs:610`). 사용자 승인된 정책이므로 이를 무조건 백업 정책으로 바꾸자는 제안은 아니다.

하지만 README의 ‘모든 작업 Undo’, ‘덮어쓰기 백업’ 설명은 실제 예외보다 넓다. `CopyMoveConfirmDialog.tsx:77`의 파일별 선택 화면은 폴더까지 포함한 Replace 개수 전체를 ‘되돌릴 수 없음’으로 표시한다(`i18n/ko.json:28`). 일반 화면에서는 복원 불가 힌트와 폴더 복원 가능 안내가 함께 나올 수 있다.

**제안:** ‘파일 2개 영구 교체 / 폴더 1개 통째 교체·복원 가능’으로 나눠 집계한다. 저널 화면에도 복원 가능 범위를 표시한다. macOS 휴지통의 앱 내 복원 제한은 해당 작업에서 Finder 복원으로 안내한다. README·DESIGN·ROADMAP·기존 리뷰의 현재 상태를 맞춘다.

**완료 기준:** 파일만/폴더만/혼합 충돌에서 일괄 선택과 파일별 선택의 안내가 일치한다. 사용자 정의 단축키를 바꿔도 Undo 안내가 따라간다.

### R05. 폴더 ‘병합’을 별도 동작으로 제공 — P1

**확인:** `ConflictPolicy`는 Skip/KeepBoth/Replace이며, 현재 폴더 Replace는 통째 교체다. 이전 리뷰에서 폴더 교체의 복원 안전망은 보완됐지만 일반적인 재귀 병합은 별개다.

예를 들어 대상 `assets`에 `old.png`가 있고 새 `assets`에 `new.png`만 있을 때, 사용자가 둘을 합치고 싶으면 통째 교체는 원하는 결과가 아니다.

**제안:** 양쪽이 폴더일 때 ‘내용 합치기’를 제공하고, 내부 동명 파일은 기존 파일별 충돌 정책으로 처리한다. 파일↔폴더 충돌과 심볼릭 링크는 별도로 다룬다. 병합을 단순한 Replace의 명칭 변경으로 구현하면 안 된다.

**완료 기준:** 대상에만 있는 파일 유지, 충돌 정책 적용, 취소·부분 실패 후 결과 집계와 Undo가 모두 정확하다. 동일 호스트 직접 전송 경로에서도 같은 의미를 보장한다.

## 5. 반복 사용의 편의성을 높일 기능

### R06. 이름 있는 작업환경과 탭 관리 — P1

**확인:** `stores/session.ts:13`은 마지막 레이아웃 하나를 복원한다. `TabBar.tsx`와 `TabState`에는 이름 있는 여러 작업환경, 탭 잠금·사용자 이름·드래그 재정렬 모델이 없다.

**제안:** ‘서버 배포’, ‘다운로드 정리’, ‘사진 선별’처럼 좌우 경로·탭·활성 패널·보기·동기화 브라우징 상태를 이름 붙여 저장한다. 우선 저장/불러오기/이름변경과 닫은 탭 다시 열기를 제공하고, 탭 잠금·재정렬을 추가한다. 잠금은 ‘경로 이동 금지’인지 ‘닫기 방지’인지 구분한다.

ForkLift Workspaces와 XYplorer Tabsets를 참고할 만하다. 현 세션 복원이 존재하므로 ‘세션 저장 신규 구현’이 아니라 다중 프리셋 확장이다. [ForkLift](https://binarynights.com/index.html), [XYplorer](https://www.xyplorer.com/product.php).

**완료 기준:** 다른 작업환경을 연 뒤 원래 작업으로 한 번에 돌아온다. 원격 호스트 미연결 상태도 경로를 잃지 않고 복구한다. 비밀번호는 작업환경에 포함하지 않는다.

### R07. 기기 간 설정 이동 — P1, 크로스플랫폼 목표에 직접 기여

**확인:** 설정·북마크 등은 설정 디렉토리 파일, 세션·컬럼 폭·밀도 등은 localStorage에 나뉘어 있다. 확인한 설정 UI와 명령 등록에서는 통합 내보내기/가져오기 흐름을 찾지 못했다.

**제안:** 1차는 자동 클라우드 동기화보다 버전 있는 프로필 파일 내보내기/가져오기다. 키맵·테마·밀도·북마크·작업환경을 한 번에 옮기되, `~/Projects`와 `D:\Projects` 같은 경로 및 외부 앱 경로는 기기별 매핑으로 해결한다. 가져오기 전에 적용·충돌·미해결 항목을 미리 보여준다.

서버 설정 이동은 Transmit, 휴대 가능한 사용자 설정은 XYplorer에서 참고할 수 있다. 이는 두 제품이 크로스플랫폼이라는 뜻은 아니다. [Transmit](https://panic.com/transmit/), [XYplorer](https://www.xyplorer.com/product.php).

**완료 기준:** macOS에서 내보낸 비밀정보 없는 프로필을 Windows/Linux로 옮겨 같은 명령과 작업환경을 사용할 수 있다. 기기별 경로가 없으면 삭제하거나 잘못 이동하지 않고 매핑을 요청한다. 자격증명·개인키·작업 저널은 기본 프로필 이동 대상에서 제외한다.

### R08. 검색 결과에서 바로 선택·작업 — P1

**확인:** `SearchPanel.tsx:305`의 결과는 개별 버튼 목록이다. `App.tsx:756`은 클릭한 결과의 폴더로 이동하고 커서를 맞춘다. 검색창은 유지되지만 검색 결과 자체의 다중 선택·복사·Shelf 추가는 없다. 숨김 포함은 `false`, 결과 상한은 500으로 지정한다.

**제안:** 단계 1은 결과 다중 선택 + Shelf 추가 + 실제 위치 열기. 단계 2는 ‘결과를 패널에서 열기’와 저장 검색이다. 파일명/내용, 검색 위치, 숨김 포함, 인덱스 기준 시각, 결과 상한을 명확히 보여준다. 내용 검색은 매칭 문맥 표시를 검토한다.

Directory Opus는 검색 결과를 컬렉션에 담아 일반 파일처럼 처리한다. 듀엣도 검색·Shelf·패널이 같은 대상 참조를 공유하면 이후 중복 파일 찾기와 하위 폴더 펼쳐보기에 재사용할 수 있다. [공식 컬렉션 설명](https://docs.dopus.com/doku.php?id=basic_concepts:virtual_file_system:file_collections).

**완료 기준:** 여러 폴더에서 찾은 파일을 검색창 안에서 선택해 한 번에 수집한다. 컬렉션에서 빼기와 원본 휴지통 보내기를 다른 동작으로 표시한다. 오래된 결과를 실행할 때 존재 여부를 다시 확인한다.

### R09. Shelf의 혼합 소스 일괄 실행 — P1

**확인:** `src/lib/fileActions.ts:559`의 `applyShelfTo`는 소스별로 그룹을 나눈 뒤 첫 그룹만 `planTransferTo`에 넘기고 나머지는 남았다는 토스트를 표시한다. 여러 위치 수집은 가능하지만 혼합 소스 전체의 한 번 실행은 미완성이다.

**제안:** 목적지를 한 번 정하고 로컬·서버별 하위 작업을 묶은 상위 작업을 만든다. 그룹별 전송 경로와 충돌을 확인하고 결과를 하나로 집계한다. 서로 다른 소스에 같은 이름이 있을 때 발생할 그룹 간 목적지 충돌도 계획에 포함한다. 성공 항목과 실패 항목을 구별해 Shelf에서 정리한다.

Path Finder Drop Stack과 QSpace Stash Shelf를 참고하되 듀엣의 같은 호스트 직접 복사 전략을 유지한다. [Path Finder](https://support.cocoatech.com/hc/en-us/articles/43505869579796-Drop-Stack-Temporary-Holding-Area-for-Files), [QSpace](https://qspace.awehunt.com/en-us/index.html).

**완료 기준:** 로컬+서버 A+서버 B의 파일을 한 작업으로 처리하고 일부 서버 실패 시 나머지 결과와 실패분을 확인한다. 재실행으로 이미 성공한 이동을 반복하지 않는다.

### R10. 탐색 맥락 복원·주소 자동완성·탭 과밀 대응 — P2

**확인:** `TabState.history`는 Location 목록과 인덱스만 저장한다(`panes.ts:52`). 뒤로/앞으로에서 과거 커서·선택·스크롤을 복원할 모델이 부족하다. `PathBar.tsx`의 경로 입력에는 후보 목록이 없고, `TabBar.tsx`는 탭을 나열하는 구조로 별도 오버플로 목록이 없다.

**제안:** 방문별 커서 항목 이름·스크롤 앵커를 저장한다. 주소 입력은 최근 경로와 실제 하위 폴더 후보를 제공하고 원격은 요청 취소·디바운스·캐시를 둔다. 탭이 많아지면 활성 탭이 보이도록 스크롤하거나 ‘열린 탭 목록’을 제공한다.

**완료 기준:** 긴 폴더 목록에서 하위 폴더에 갔다 돌아왔을 때 같은 위치가 보인다. 긴 호스트 이름·긴 탭 이름 15개에서도 활성 탭과 새 탭 버튼에 접근할 수 있다. 주소 자동완성은 QSpace의 참고 포인트다. [QSpace](https://qspace.awehunt.com/en-us/index.html).

### R11. 폴더별 보기와 보조 UI의 공간 배분 — P2

**확인:** 밀도와 컬럼 폭 조절은 이미 있다. 컬럼 폭은 `stores/columnWidths.ts`의 전역 값이며, 현재 탭의 정렬·보기와 폴더별 영속 프리셋은 다르다. 상단 툴바는 고정된 여러 아이콘과 앱 런처를 함께 배치한다.

**제안:** 사진 폴더는 Grid, 다운로드는 날짜 정렬, 로그는 수정일 중심 등 ‘이 폴더 보기 기억’을 제공한다. 툴바에는 자주 쓰는 동작만 남기도록 사용자 배치를 검토한다. 작은 창에서는 보조 패널 자동 축소보다 사용자가 고른 보기 프리셋으로 명시적으로 전환하는 방법이 예측하기 쉽다.

XYplorer의 폴더별 보기, ForkLift의 툴바 조절을 참고한다. 실제 잘림·가독성 문제는 화면 측정 후 판단해야 하므로 이번에는 레이아웃 버그로 확정하지 않는다. [XYplorer](https://www.xyplorer.com/product.php), [ForkLift GUI 안내](https://binarynights.com/manual).

**완료 기준:** 1280×800과 1920×1080에서 사이드바·미리보기를 켠 상태로 긴 파일명을 구분할 수 있다. 100%/150%/200% 배율과 라이트/다크를 확인한다.

### R12. 키보드·포커스·OS 관례를 하나의 조작 규칙으로 정리 — P1/P2

**확인:** 키맵과 플랫폼별 표기는 이미 있다. 그러나 `useEntryDrag.ts:57`은 드래그 시작 시 Ctrl 또는 Shift로 이동을 정하며 키맵 경로와 독립적이다. `TopBar.tsx:179`의 창 버튼은 공통 Windows식 구성이다. `TabBar.tsx`의 클릭 가능한 탭 div와 `EntryRow.tsx`의 행에는 탭/선택 상태 의미 속성이 없다. 일부 작은 취소 버튼은 아이콘 11px+작은 패딩이다.

**제안:**

- ‘듀엣 공통 / TC 중심 / OS 기본’ 조작 프리셋을 검토하되, 한 번 고른 의미가 모든 화면에서 유지되게 한다. 화면 문구는 실제 유효 바인딩에서 만든다.
- 드래그 고스트에 ‘복사 8개 → 대상’ 또는 ‘이동 8개 → 대상’을 명시한다. 현재 네이티브 드래그의 시작 시 확정 제약을 유지하면서 먼저 가시성을 개선한다.
- 창 버튼의 OS 관례 적용 여부는 별도 선택 사항이다. 사용자 목표인 동일 경험을 고려하면 이를 자동으로 결함 판정할 수 없다.
- 파일 목록·탭에 선택 상태와 포커스 의미를 제공하고 다이얼로그 종료 후 원래 대상으로 포커스를 돌린다. 작은 아이콘을 유지해도 클릭 영역은 프로젝트 기준 24px 이상으로 확보한다.
- Undo 버튼 우클릭에 숨은 히스토리(`TopBar.tsx:138`)는 드롭다운 등 눈에 보이는 진입점을 둔다.

**완료 기준:** 마우스 없이 목록→선택→작업→결과 확인→목록 복귀가 가능하다. 한글 IME 조합 중 단축키가 오작동하지 않는다. 화면 읽기 도구로 활성 패널·선택 개수·진행 상태를 구분한다. 이는 접근성 인증 결과가 아니라 향후 실기 검증 기준이다.

## 7. 실행 순서와 검증 계획

규모 S는 제한된 UI·문구 작업, M은 여러 화면 또는 IPC 확장, L은 작업 모델·영속성·실패 복구 설계까지 필요한 작업이다. 확정 공수는 아니다.

| 묶음 | 작업 | 대략 규모 | 선행 조건 |
|---|---|---|---|
| A — 정확성과 안내 | R01 동명 편집 격리, R02 미지원 필터 처리, R04 문구·문서 정합성 | M / S~M / S | 현재 동작 재현 fixture |
| B — 결과를 끝까지 확인 | R03 작업 결과 보존→구조화 결과→실패분 재시도, R01 업로드 상태·충돌 처리 | M→L | 작업별 결과 모델 |
| C — 반복 작업 단축 | R06 작업환경, R08 검색→Shelf, R09 혼합 소스 실행 | M / M / L | 혼합 소스 실행은 B 기반 |
| D — 크로스플랫폼 완성도 | R07 프로필 이동, R12 조작·포커스, R10/R11 탐색·보기 | M~L | 경로·키맵 매핑 규칙 |
| 별도 기능 작업 | R05 재귀 병합 | L | 항목별 충돌·Undo·부분 실패 설계 |

가장 작은 첫 묶음은 **원격 동명 편집 격리 + 원격 필터 오안내 제거 + 복원 문구 정정**이다. 다음 사용자 체감 개선으로는 **작업 센터 + 이름 있는 작업환경**을 권한다.

실기 검증은 사용자 홈이나 운영 서버 대신 별도 fixture 디렉토리·테스트 서버에서 수행한다.

## 9. 후속 구현 기록 — 2026-09-11

사용자 요청에 따라 1차 수정 묶음을 구현했다. 본문은 수정 전 검토 기록이며, 아래 상태가
후속 구현 결과다. 제품 코드 변경 없이 보고서만 작성했다는 서두는 최초 검토 시점 기준이다.

| 항목 | 이번 구현 | 남은 범위 |
|---|---|---|
| R01 | 연결·전체 원격 경로별 편집 세션, 고유 임시 폴더, 반복/동시 열기 사본 보존·단일 watcher, 에디터 실행 전 변경 기준 확보 | 업로드 상태 UI, 원격 외부 변경 감지, Undo 정책, 재시작 복구 |
| R02 | 원격 파일명 검색의 메타 필터 비활성화·설명, IPC 미지원 오류, 로컬 필터 선택 보존 | 원격 메타데이터 수집, 내용 검색 필터 지원 |
| R04 | 파일·폴더별 교체 개수/복원 안내 통일, 사용자 Undo 키 반영, 정책 문서 정정 | 저널 화면의 상세 복원 범위, macOS 휴지통 안내 추가 |

새 의존성과 IPC 타입 변경 없이 적용했다. 테스트는 임시 fixture·모킹을 사용하며 실제
사용자 서버에 접속하거나 파일을 편집하지 않았다. 작업 센터·작업환경·폴더 병합은 이 묶음에
포함하지 않았다.

검증 결과: 프론트엔드 45개 파일·320개 테스트 통과, Rust 라이브러리 356개 통과·1개
기존 ignored. TypeScript, ESLint, 변경 UI/번역 파일 Prettier, Rust fmt·Clippy,
Vite 프로덕션 빌드, diff whitespace 검사 통과. Vite의 500KB 초과 청크 경고는 남아 있다.
실제 SSH·외부 에디터·OS별 GUI 통합 검증은 수행하지 않았다.


### R01 재열기 회귀 수정

초기 수정은 앱 실행 중 사본을 계속 재사용해 서버 변경을 놓쳤다. 후속 수정은 로컬
사본의 수정 시각과 마지막 업로드 기준이 같을 때만 서버에서 갱신한다. 미업로드 편집은
보존하고, 사본이 사라진 경우 새 사본과 watcher로 복구한다. 갱신과 업로드는 같은 잠금으로
직렬화하며 다운로드 도중 로컬 사본 변경 여부를 다시 확인한다. 기존 ‘사본 소실 시 오류’
테스트를 복구 검증으로 바꾸고 업로드 완료→서버 변경→재열기 회귀 테스트를 추가했다.
미사용 `conflict.replaceAllHint` 번역도 제거했다.

후속 검증: 원격 편집 회귀 테스트 4개, 충돌 UI 테스트 15개 통과. Rust fmt·기본
Clippy(`-D warnings`)·번역 Prettier·diff 검사 통과. 이번 후속에서는 전체 테스트와
`clippy --all-targets`를 재실행하지 않았다. 실제 SSH/에디터 검증은 남아 있다.
