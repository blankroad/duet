# remote 점검 최종 보고

## 요약

- SSH 연결·원격 파일시스템의 기본 경로(키/비번 접속, SFTP 목록·읽기·쓰기·이름 변경, 원격 휴지통·복원, 같은 서버 복사)는 실서버(docker sshd)에서 **동작한다**. 기존 `ssh_it_*` 18개 전부 통과. 셸 인젝션은 전 호출부에서 막혀 있고, 휴지통 실패 시 rm 으로 넘어가는 일도 없다.
- 이슈 **35건: P1 2 · P2 16 · P3 17**. 거의 전부 실행으로 재현했고, 2인 교차 검토에서 사실관계 반박은 없었다(심각도 조정 2건).
- **가장 중요한 것 (P1)**
  - **remote-01**: 리눅스 서버에서 이름에 `\` 가 든 항목을 같은 서버 안에서 복사/동기화하면, 엉뚱한 파일을 복사하고 받는 폴더의 무관한 파일을 백업 없이 덮어쓴다(Skip 이어도). sync 는 엉뚱한 폴더를 정리(prune)하고, Ctrl+Z 는 "성공"하는데 엉뚱한 곳에 복원한다.
  - **remote-02**: ProxyJump 로 처음 접속하거나 키 변경 경고를 승인할 때, 사용자는 점프 호스트의 지문 하나만 보는데 **대상 서버 키까지 함께 신뢰·교체**된다.
- Windows 사용자에게 특히 걸리는 것: Windows 에이전트(OpenSSH agent/Pageant) 미지원(remote-15), 암호 걸린 키의 passphrase 입력 경로 없음(remote-16, 이때 passphrase 가 서버 로그인 비번으로 전송될 수 있음), 원격 KeepBoth 경로가 `\` 로 깨짐(remote-17), 신뢰 저장소가 `~\ssh` 로 OpenSSH 와 다름(remote-20).

## 다른 영역으로 넘긴 것

- **archive (§5, 중요)**: 원격 암호 zip 을 `unzip -P '<암호>'` 로 실행해 서버 프로세스 목록에 암호가 보임. 전송 오류 시 `exec '<cmd>': …` 오류에 암호가 든 명령 전체가 담겨 토스트·알림 "자세히"까지 감(sol R2 가 경로 확정: remote_exec.rs:33-36 → fs_ops.rs:1521/1585 → NoticeBadge). 또 archive.rs 의 `shell_escape_path`(remote-01 파급), `open_for_browse` 의 native join(Windows).
- **fileops**: sudo Replace 가 백업을 영구 삭제하고 폴더 교체 undo 가 없음(§4), sudo Skip 이동 시 원본까지 휴지통으로 가는지 의심(sol), relay `.duet-part` 잔존 정책(remote-23), 실행 중 cp/rsync 취소 불가(remote-07).
- **browse**: edit_session 이 원격 basename 을 다루는 방식(Windows `\`), paths.ts 표시.
- **shell-settings**: settings/bookmarks/user_aliases 도 제자리 쓰기 + 시작 `.expect` (remote-19 와 같은 패턴).
