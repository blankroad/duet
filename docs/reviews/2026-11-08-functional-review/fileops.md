# fileops 점검 최종 보고

## 요약

- 파일 작업의 정상 경로(로컬 복사·이동·충돌 3정책·폴더 교체 undo·삭제 게이트·휴지통 put back·권한/새 항목)는 실행으로 확인했고 동작한다. 문제는 **되돌리기(undo/redo) 엔진**과 **실패·경계 경로**에 몰려 있다.
- 이슈 36건: **P1 6 · P2 18 · P3 12.** 전부 교차 검토를 거쳤다(R1→R2→R3). 미결은 없다. 기기 확인이 필요한 것은 따로 모았다.
- 가장 중요한 것: ① 작업 기록 파일(journal.jsonl)이 동시 기록 2건만으로 깨지고, 깨지면 **앱이 켜지지 않는다**(fileops-01). ② Ctrl+Z 가 **영구 삭제**(복사 되돌리기)나 **새 파일 덮어쓰기**(이름 바꾸기·이동 되돌리기, 일괄 이름 바꾸기 다시 실행)를 한다(02·03). ③ 폴더를 자기 하위로 복사하면 Windows 에서 원본 ×100 이상으로 불어나 디스크를 채울 수 있다(04, 지난 보류 B-05 실증). ④ 같은 IP 의 다른 서버(Vagrant·도커·포트 포워딩)를 같은 호스트로 보고 **엉뚱한 서버에 기록**한다(05). ⑤ Ctrl+Z 가 한 번 건너뜀/오류에 걸리면 그 뒤로 영원히 막힌다(06).
- Windows 크로스 clippy 는 제품 코드 경고 0. Windows 실기·실앱·실서버는 실행하지 않았다(규칙).

## 개선 제안

- **오류 사유 구조화**: `RollbackFailed{backup}`·`IntoItself`·`CaseOnlyRename` 등을 DuetError 로 내려 explainError 주 문구에 원인·복구 위치를 싣기 — 04·08·09·17 의 "이해 못 할 실패"를 한 번에 해결.
- **드래그 수정 키(사용자 결정)**: DESIGN.md 는 Ctrl(·Shift·Cmd)=이동. Windows 탐색기 관례는 Ctrl=복사·Shift=이동이고 기본 `conflicts_only` 라 확인 없이 이동된다. 관례를 따를지 결정 필요.
- OS 클립보드 읽기(탐색기/Finder 에서 복사한 파일을 duet 에 붙여넣기) 지원.
- 승격 재시도는 원래 plan 전체를 다시 실행 — 일부가 이미 처리됐으면 KeepBoth 중복, 이동은 "원본 없음".
- 알려진 보류 재확인: "충돌 결정 단일 task", "task 제목 i18n" (변동 없음).
