    사용자가 짚은 불편 네 가지를 모두 고쳤다. 숨김 토글은 다시 툴바 1클릭이다. 원격 탭에는 호스트와 연결 상태 칩이 상시 표시된다. 탭을 핀으로 고정할 수 있고, 배너 [재연결]은 패널을 묻지 않고 원래 탭으로 돌아간다. 이와 함께 6개 컴포넌트를 병렬로 리뷰해 버그와 불편을 고쳤다.

    결과는 커밋 151개(파일 157개, +13,687 / −1,713)이며, 새 의존성은 없고 백엔드 변경은 1개 파일이다. 실 SSH 서버 왕복과 Windows 실기는 확인하지 못했다. 백엔드 복사 경로 검사(B-05) 등 사용자 결정이 필요한 보류 항목이 남아 있다.

    배경

    전반적인 만족도는 높지만, 사용하면서 다음 네 가지가 걸린다는 피드백이 있었다.

    1. 숨김 파일 토글이 한 단계 아래로 내려감. 원인은 4057333(2026-09-11)의 "패널 폭 560px 미만이면 메뉴로" 규칙이다. 기본 창(1280px + 사이드바 + 미리보기)에서 패널 폭은 약 383px이라, 토글이 사실상 항상 보기 메뉴 안에 있었다.
    2. 현재 탭이 원격인지 알기 어려움. 경로 바에 원격 표시가 약했고, 비활성 탭의 끊김은 아예 보이지 않았다.
    3. 탭 핀 고정 없음.
    4. 배너 [재연결] 후 "어느 패널에 띄울까"를 다시 물음. 재연결이 일반 연결 대화상자를 그대로 재사용했기 때문이다.

    이 네 가지를 출발점으로 삼되, 같은 종류의 "미묘한 불편"이 더 있을 것으로 보고 컴포넌트 단위로 전체 리뷰를 진행했다.

    phases

    사용자 지적 4건의 해결

    숨김 파일 토글 (pane-chrome)

    모든 패널 폭에서 숨김 토글을 툴바 버튼으로 되돌렸다. 켜진 상태는 배경 채움(bg-active)과 눈 아이콘으로 표시한다. 툴팁에는 현재 할당된 키가 나온다(키 하드코딩 없음). 보기 메뉴의 항목도 그대로 남겼다. 폭 단계는 헤드리스 Chrome으로 280~720px를 1px 간격으로, 한/영 × 동기화 켬/끔 조합(1,764가지)에서 측정해 다시 정했으며 넘침은 0건이다.

    원격 탭 식별 (tabs)

    • 경로 바 왼쪽 SourceChip: 원격이면 Server 아이콘과 호스트 별명이 accent 칩으로 나온다. 연결 중이면 회전 아이콘, 끊김·오류면 Unplug 아이콘에 danger 테두리를 쓴다. 경로 편집·아카이브·휴지통 화면에서도 칩은 유지된다.
    • 탭에도 같은 아이콘과 호스트 이름을 붙여, 비활성 탭이 끊겨도 보인다. 툴팁에는 호스트, user@ip, 상태, 전체 경로가 나온다.
    • 로컬 탭은 칩을 조용하게 둔다. 원격일 때만 눈에 띈다.

    탭 핀 고정 (tabs)

    탭 우클릭 "탭 고정" 또는 명령 tab.togglePin으로 고정한다. 고정 탭은 왼쪽에 모이고, 구분선과 짧은 라벨을 쓰며, X 대신 핀 버튼이 붙는다. 세션에 저장되고, 구버전 세션도 그대로 읽힌다. 닫기 보호는 UI가 아니라 store에 두어서 X·가운데 클릭·Ctrl+W·팔레트·일괄 닫기 어느 경로로도 고정 탭이 닫히지 않는다.

    src/stores/panes.ts (발췌)
    /** 앞쪽 연속 핀 구간의 길이 = 첫 일반 탭의 인덱스. */
export function pinnedCount(p: PaneState): number {
  let k = 0;
  while (k < p.tabs.length && p.tabs[k]!.pinned) k += 1;
  return k;
}

    키, 에이전트, 저장된 vault 비밀번호로 붙는 호스트는 대화상자 없이 재연결된다. 비밀번호나 호스트 키 승인이 필요할 때만 대화상자가 뜨며, 이때 패널은 고정되고 선택지가 없다. 실패 사유와 호스트 키 프롬프트는 처음부터 보인다. 같은 호스트를 쓰던 다른 탭(양쪽 패널, 비활성 탭, 뒤로가기 기록)도 새 연결로 함께 살아난다. 연결을 기다리는 사이 사용자가 그 탭에서 다른 폴더로 이동했다면 덮어쓰지 않는다.

    보안 (§5)

    같은 작업에서 세 가지를 고쳤다. 저장 호스트로 프리필한 뒤 주소를 고치면 저장 비밀번호가 새 주소로 전송되던 문제, 호스트 키 승인 대상이 바뀔 수 있던 문제, 비밀번호 입력칸이 호출 직후 비워지지 않던 문제다. 평문 비밀번호를 프론트로 되돌리는 경로는 없다.

    숨김 토글이 메뉴로 숨은 근본 원인은 폭 단계 규칙이었다. 그래서 규칙 자체를 어떻게 둘지 비교했다.

    안장점단점결정
    A. 고정 임계값 단계형 + 실측으로 재조정단순하고 테스트 가능. 넘침 0을 측정으로 보장버튼이 늘면 단계를 다시 측정해야 함채택
    B. ResizeObserver로 넘치는 버튼만 "더보기" (VS Code식)공간 효율 최고복잡하고 jsdom 테스트가 어려움. 어떤 버튼이 숨을지 예측하기 어려움제외 (버튼이 더 늘면 재검토)
    C. 기존 규칙 유지, 숨김 토글만 예외변경 최소필터·정렬도 같은 문제. 예외가 쌓임제외

    새로 발견한 문제 (미수정)

    1. 개발 빌드에서 세션 복원 활성 탭이 틀어진다. React StrictMode가 부트스트랩 effect를 두 번 실행한다. 두 번째 실행이 첫 실행 루프가 바꾼 activeTabIndex를 "저장된 값"으로 읽는다(App.tsx 부트스트랩의 savedActive). 원래 main에 있던 코드이고 프로덕션에서는 재현되지 않을 것으로 보이지만, 부트스트랩을 멱등하게 만드는 편이 안전하다.
    2. 끊긴 원격 패널이 배너 아래에 "빈 폴더입니다"를 표시한다. 폴더가 비어 있는 게 아니라 연결이 없는 상태이므로 문구를 구분해야 한다.
