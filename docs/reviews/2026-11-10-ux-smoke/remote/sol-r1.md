## Ranked new findings — 3 confirmed gaps

1. **P2 remote-NEW-2 — healthy saved/ad-hoc connections cannot be explicitly disconnected through the UI.** Saved-host context menu offers Connect/Edit and Remove, but no Disconnect (`src/components/Sidebar.tsx:1247`); only config-host rows offer Disconnect (`:1802`). A healthy remote pane hides its banner (`src/components/pane/ConnectionBanner.tsx:70`), pane menus offer no disconnect, and palette/keymap command registries contain connect entries only (`src/lib/commands.ts:466`, `src/lib/dynamicCommands.ts:49`). Closing a tab only removes pane state (`src/stores/panes.ts:407`). Custom saved aliases also fail to match canonical `user@host:port` active aliases for state/badges (`Sidebar.tsx:1245`). Evidence: **mocked FE test** `remote-sol-r1-saved-disconnect.test.tsx:92` fails because menu ids do not contain `disconnect`; static reading confirms no alternate healthy-session close entry. This is separate from known remote-07 backend close blocking.
2. **P2 remote-NEW-3 — valid config aliases colliding with Object.prototype become permanently “reconnecting”.** `constructor`, `toString`, `__proto__` match `alias in {}` before any request. Host activation stops with the in-progress toast (`src/App.tsx:1740`); disconnected/restored banner shows progress without Reconnect or Stop (`src/components/pane/ConnectionBanner.tsx:63`, `:88`), and registry updates treat them as already present (`src/stores/connections.ts:126`). Evidence: **mocked FE test**, three cases in `remote-sol-r1-prototype-alias.test.tsx:37`: only a reconnecting status is rendered, no Reconnect button. Host-activation extension is static reading. Fix needs own-property checks / a safe keyed collection at all consumers, not just one banner.
3. **P2 remote-NEW-1 — successful connect silently discards host/password save failures.** Ad-hoc “Save host” ignores `saveHost`'s false result (`src/components/connection/AdHocConnectDialog.tsx:277`, `src/stores/savedHosts.ts:30`); unlocked and deferred password flows ignore `vaultSet`'s false result (`AdHocConnectDialog.tsx:296`, `:305`, `src/stores/vault.ts:47`). It then navigates/resets/closes exactly as successful saving (`AdHocConnectDialog.tsx:313`). User discovers missing host/secret on the next connection. Evidence: **mocked FE test**, two disk-full cases in `remote-sol-r1-save-failure.test.tsx:82`: `onClose` called once despite failed save; successful connection and save-command invocation are preconditions. Separate from remote-19 corruption and fixed remote-22 backend durability.
