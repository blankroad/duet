## Findings requiring changes

1. **P1 — Folder-mode Replace can move another selected source archive.** `core/archive_batch.rs:89-111` checks destination existence and output-name claims, but never protects selected input paths; `archive.rs:285-306` backs up a conflicting destination without source protection. Concrete ordinary input: select `a.zip.gz` (gzip of zip bytes) and `a.zip`, choose each-to-folder then Replace. The gzip's stem is `a.zip`; plan marks it conflict=true/keep_both=false. Executing it renames the selected source `a.zip` to `.bak` and writes decompressed bytes at its path. With different gzip contents the later a.zip task reads different bytes / fails. Even with identical bytes the source was moved/renamed, violating explicit “Source archives are never moved, renamed or deleted.” This is not an external race. Here-mode's protect list does not cover folder-mode. Reserve all selected source paths during batch naming and force KeepBoth/alternate destination when a destination equals a source, including repeated password execution. Required regression: `a.zip.gz` + `a.zip`, Replace, both sources remain byte-identical at original paths and both outputs distinct. Static trace, no cargo reproduction claimed.

2. **P1 — Cancel-to-next password prompt can reuse the prior archive's local password state.** `App.tsx:2262-2278` renders PasswordPromptDialog without a key; `extractPending.ts:90-95` synchronously opens the next prompt when dialog closes. With B waiting, type a secret into A's input and cancel A. Store changes none→B in the same event; React can retain the same PasswordPromptDialog at the same position, since component type/key did not change. PasswordPromptDialog initializes pw/error/busy once with useState, never resets on archiveName; cancel does not clear pw. B therefore inherits A's typed secret/error state; Enter can submit A's secret to B without intentionally entering B's password. This violates no cross-archive reuse and cancel-skips-one intent. The existing FIFO test only checks store dialog values and cannot detect mounted component state retention. Give each prompt a stable unique prompt identity/key (including repeated same-name archives), reset sensitive state on transition/cancel, and guard late submit/onClose from A so it cannot close B after an in-flight cancel. Add a rendered two-prompt test: type into A, Cancel, B input empty, no prior wrong-password state; cancel while A's enqueue promise is pending must not close B on late resolution. Static React/store trace, not a newly run mounted integration repro.

3. **P2 — Journal-failure rollback can falsely claim complete rollback on stat failure.** `archive_here.rs:327-341` treats every error checking backup existence as “restored”, and every error checking created paths as “absent”; undo_cleanup outcome is only traced. Concrete injected/permission scenario: journal append fails; rollback resolver cannot access paths or undo returns Error; fs.symlink_metadata also returns PermissionDenied. Both lists become empty and error text says “it was rolled back”, despite outputs/backup still being present and no undo history entry. The new bounded rollback is useful, but this verification must recognize only NotFound as absence and preserve unknown paths/outcome errors for recovery reporting, just as cleanup_staging was corrected. Add a failed-rollback + metadata-error test, not merely a trash failure with readable paths. Static branch trace; no cargo run.
