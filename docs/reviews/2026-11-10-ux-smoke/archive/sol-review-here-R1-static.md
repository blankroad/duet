## Numbered findings

1. **P1 — Journal write failure leaves changes without a Ctrl+Z entry.** Current `archive_here.rs:204-231` performs placement, disposes staging, computes stamps, then `ctx.journal.push(op, undo).await?`. `Journal::push` appends to disk before inserting into memory (`services/journal.rs:403-419`). Concrete scenario: Replace readme.txt succeeds (old contents in .bak, new contents in place), but journal directory is unwritable or disk/quota is full. Push returns error; no entry is in history and engine does not roll back or return a recoverable mutation manifest. Thus “every change is journaled, even failure” is conditional on successful journal persistence, not guaranteed by this implementation. Existing partial-rename test checks a placement failure with a healthy journal, not a failing journal. Need preflight plus a durable recovery/write-ahead design or safe rollback/recovery handling; a preflight alone cannot guarantee a later append succeeds. This gap is shared with other post-operation journal patterns, but the new engine cannot claim unconditional §4 compliance.

2. **P2 — Leftover staging paths are silently lost for non-Io errors.** `cleanup_staging` returns Some(path) on trash failure, but `with_leftover` (`archive_here.rs:469-475`) attaches it only to DuetError::Io. Concrete scenario: an encrypted archive leaves partially unpacked staging, extract_local returns NeedPassword, trash fails (permissions/trash unavailable). Caller receives bare NeedPassword and no summary; the leftover path is discarded. Same issue for Cancelled/PermissionDenied failures; partial-placement summary is also discarded on Err. SPEC A.4 explicitly requires path in error/summary when cleanup fails. Preserve the original error kind for password handling and surface cleanup detail through a structured error/notice side channel. `cleanup_staging` also treats *any* symlink_metadata error as “gone” (lines 443-445); PermissionDenied must not be treated as confirmed NotFound. No failure-injected test run; concrete branch trace only.

3. **P2 — The new “still our placeholder” claim overstates what is checked.** `still_placeholder` (`archive_here.rs:413-418`) checks only regular-file kind and size==0, not identity. Concrete scenario: after reservation an external writer deletes the placeholder and creates its own empty file; even before the check, that foreign empty file passes and is replaced. This is more than the documented check-to-rename gap. The module now honestly describes external races as best effort, so this is not an assertion that the declared external-writer guarantee must become absolute. Tighten wording to “a zero-byte regular file still occupies the path”; if claiming ownership, retain/check identity. No inode/file-handle ownership proof exists. Directory bulk fill similarly makes no child reservations; see guarantee assessment below.

## Requested guarantee assessment

(a) **What holds:** `try_reserve` creates a directory or exclusive empty file; at that operation the *final path entry* already present is not replaced. KeepBoth tries numbered candidates; Skip does not intentionally move an existing conflicting entry. Reservation-time collision handling is sound in ordinary stable-parent operation. This is not an atomic reserve-and-fill transaction. Later `rename(staged,target)` replaces a placeholder path, and fresh-directory fill does ordinary child renames. External writers can replace a child, write after placeholder check, replace a placeholder with another empty file, or replace an ancestor with a symlink. Existing ancestor symlinks also matter: lstat checks only the final target, not every ancestor. A pathname reservation does not defend ancestor replacement.

Original 9b661ac prose (“nothing appearing in between overwritten”) was too strong. **0c18851 substantially corrects it**: explicitly calls external placeholder/child/ancestor races best effort. TaskQueue uses one FIFO worker per HostKey; enqueue_extract_here uses host_key_for_op(local,local), so cooperating extract tasks through that queue serialize. This is not a global filesystem lock: external programs, core direct callers and operations outside that queue remain outside the guarantee. Spec's literal “KeepBoth never replaces anything even on a race” is therefore fulfilled for pre-reservation occupancy/cooperating queued tasks, not arbitrary external mutation. Lead/product should retain this scope explicitly; do not advertise universal no-overwrite. Finding 3 is the remaining wording precision issue.

(b) **Merge/source protection:** placement lstat's staged node and existing final target. A stable symlink-to-directory target is treated as a conflict, never selected as a directory merge; symlink children of a fresh dir move as links. This is “does not deliberately merge through a symlink detected at the target,” not race-proof no-follow traversal. Replace calls is_protected before moving conflict target. Current archive always appended to protection; stable same-folder regular sibling sources supplied by backend are protected (case-insensitive conservative string comparison). Protected conflict falls back to KeepBoth; original archive paths are not intentionally moved. Source aliases/path normalization and outside actors are not an identity proof; no new ordinary stable-path bypass identified.

(c) **Undo/delete:** created fresh dirs are recorded before child movement, file paths recorded after success or failed rename placeholders, Replace backup recorded immediately after rename. Existing dir merges record newly created descendants rather than the pre-existing parent. Successful persistence therefore provides an UndoCopy manifest for ordinary partial placement failures. copied_stamps are computed after placement; stamp failure becomes None and undo conservatively skips unverifiable paths, so even successful journal persistence is not unconditional successful undo. Generic undo trashes unchanged created outputs then restores backups; backup.applied=None is compatible when created target is first removed. No direct fs.remove/remove_dir_all in engine placement or staging cleanup; nonempty staging goes to fs.trash, empty dirs to remove_empty_dir. Finding 1 is the important unhandled journal persistence failure. External-race loss is outside the claimed undo guarantee: overwritten external bytes are not backed up.

(d) **Cleanup/cancel:** NeedPassword/damaged extraction errors call cleanup before returning. Placement errors/cancel also clean staging and attempt a journal when mutations exist. Initial cancellation checked after staging mkdir; placement stack checks token between jobs. extract_local receives no cancel token, and fresh-dir fill's bulk child loop does not check cancellation between child renames: cancellation may wait for a full extraction/large fresh-dir fill. This is a responsiveness limitation, not proof of rollback cancellation; no external cancellation tests executed. On successful cleanup normal staging is gone (or trashed). Cleanup failure reporting is incomplete as finding 2 describes. Staging is extracted data, not moved source data; trashing leftovers does not remove source archives.

(e) **Password retry protect list:** original engine API already accepts `protect: &[PathBuf]`; original command 377ab7e retry passed Vec::new(), leaving siblings unprotected. **d5c8309 fixes command plumbing:** retry now requires original `batch: Vec<EntryRef>`, calls protected_sources, forwards resulting protect list to enqueue/engine. protected_sources revalidates same source+folder and regular file before retaining a path. Added engine test constructs encrypted a.zip containing b.zip and verifies sibling source b.zip retained with Replace retry — inspected, NOT run. 225ceeb retry union retains batch and extractActions passes it to fsExtractHereRetry, making FE integration straightforward. **225ceeb is explicitly WIP/not wired/type-clean**; no end-to-end retry completion approval. BE batch continuity is fixed statically; final FE must retain original batch through every retry and cancellation path.
