# Workflow catalog per module (research-opus, TASK B)

Base `76b9b6e`. A map for module leads: for each major user workflow, where it starts, which files carry it,
which IPC command it calls, which tests already cover it, and which known gaps apply (IDs refer to
`research/opus-prior-issues.md`).

- **Every mapping here is STATIC**: read from code at base. The caller→command map was produced mechanically with a
  Python scan of `commands.X(` call sites in non-test `src/`.
- **"Tests" lists existing automated coverage by file. I did not run them** (resource freeze, lead instruction).
  `FE-mock` = Vitest with IPC mocked (**not a live-app test**). `cargo` = Rust unit/integration.
  `docker-IT` = `scripts/ssh-it.sh` (`DUET_SSH_IT=1`, `#[ignore]`-gated). `review/*` = repro tests merged from the
  11-08 review; they may still be `it.fails`/`#[ignore]`, see Task A.
- **Selection** = which selection shapes the entry point accepts, read from `entryMenu.tsx`, `fileActions.ts` and
  `App.tsx`. The Sol worker owns the full action-availability trace; this is only the summary needed to read the map.

## Cross-module notes for leads

1. **`entryMenu.tsx` and `App.tsx` `openEntryMenuAt` are the shared hot spot**: archive (extract gating), shell
   (More options gating), fileops (paste-into/batch rename) and browse (bookmark target). Agree on edits before
   changing them (PROTOCOL).
2. **No availability framework exists.** Menu items are added or removed with inline `multi`/`isDir`/source checks.
   Palette commands have no enabled state, so wrong-context commands fail at run time (11-04 deferred). Any "disable
   with reason" work is cross-module (shell + browse) and should be one contract.
3. **Selection source of truth:** `resolveActiveTargets()` (`fileActions.ts:54`) uses `tab.selected`, or the cursor
   when nothing is selected. It is not filtered by the visible list (browse-03). Every action that takes selected
   items inherits this.
4. **Coverage holes** (no automated test found, STATIC):
   - Windows shell menu backend (`platform/shell_menu.rs` has no tests) and the App-level More-options gating.
   - Multi-selection extract: does not exist.
   - Compress dialog: no FE test.
   - `task_queue.rs` cancel paths: 1 unit test.
   - Archive cancel and rollback: only `#[ignore]` repros.
